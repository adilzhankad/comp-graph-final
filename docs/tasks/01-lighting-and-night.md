**Закрывает:** R4 / A3 (6 баллов — самый дорогой незакрытый подкритерий) и

## Задача

Формально R4 закрыт: источников два, один из них движется. Но террейн освещён
только ambient+diffuse, без спекуляра — на полный балл A3 нужен per-fragment
Блинн-Фонг со всеми тремя составляющими.

Вторая половина задачи — перевести сцену в ночь. Тема проекта («Mountain Lake &
Aurora», ночное небо с авророй) этого требует, а аврора при дневном свете просто
не читается. Чем позже мы переключимся, тем больше чужой работы придётся
перетюнивать, поэтому это делается сейчас.

## Что сделать

### 1. Проходы `Scene::render` *(уже сделано)*

Разрезано вместе с маяком — метод на объект плюс общая структура `Frame`.
Добавляешь объект — добавляешь свой метод и одну строку вызова:

```cpp
void Scene::render(const Camera& camera, float aspect, const SceneSettings& settings) {
    const Frame frame{camera.view(), camera.projection(aspect), camera.position, settings};
    setupState(settings);
    renderTerrain(frame);
    renderLake(frame);
}
```

Общие данные (view, projection, позиция камеры, оба источника света, время,
`uFogColor`, половина размера террейна) уже лежат в `Frame`, а ставит их на
шейдер `Scene::applyFrame`. Тебе остаётся дописать туда поля луны.

Фактическая сигнатура чуть другая — смотри `src/Scene.cpp`.

### 2. `src/Lights.h`

Новый заголовок, без зависимости от OpenGL:

```cpp
struct DirectionalLight {
    glm::vec3 direction{0.0f, 1.0f, 0.0f};   // в сторону источника, нормализован
    glm::vec3 color{1.0f};
};

struct PointLight {
    glm::vec3 position{0.0f};
    glm::vec3 color{1.0f};
    float linear = 0.14f;
    float quadratic = 0.06f;
    bool enabled = true;
};

struct Lights {
    DirectionalLight moon;
    PointLight fire;
};
```

Прожектор маяка уже описан как данные в `src/Beacon.h` и тоже не зависит от
OpenGL. Когда будешь делать `Lights`, забери `Beacon` туда третьим полем, а не
заводи рядом вторую систему источников: шейдеры получают его через
`shaders/beacon.glsl`, и ломать этот контракт не нужно.

В GLSL объявляй такие же структуры, а из C++ ставь юниформы по именам полей —
`glGetUniformLocation` понимает `uMoon.direction`, так что имеющегося
`Shader::set` хватает, новых перегрузок не нужно.

Геометрии костра ещё нет (её делает задание 04). Поставь точечный свет в
константную точку на берегу и оставь комментарий, что 04 привяжет его к узлу
костра. Координату возьми так, чтобы она была над водой: `Heightmap::heightAt`
даёт высоту земли, `mla::world::waterLevel` — уровень воды.

### 3. Блинн-Фонг на фрагмент

Одна и та же модель в `terrain.frag` и `lake.frag`:

```
L = k_a·I_a + Σ_lights att · ( k_d·max(n·l, 0) + k_s·max(n·h, 0)^shininess ) · I_light
h   = normalize(l + v)
att = 1 / (1 + k_l·d + k_q·d²)        — только для точечных источников
```

- Террейн: нормали оставь **плоскими** (`flat` интерполяция) — это осознанная
  художественная установка, ломать её нельзя. Спекуляр добавь слабый и с низкой
  экспонентой (камень и трава матовые), иначе грани заблестят как пластик.
- Вода: доля Блинна-Фонга там уже есть, ей нужен второй источник. Блик от костра
  на воде — это самая зрелищная часть кадра, не потеряй её.
- Гамма-коррекция `pow(color, 1/2.2)` применяется **один раз в конце**, после
  суммирования всех источников. Сейчас так и сделано, не продублируй.

### 4. Мерцание костра

Сумма синусов на несоизмеримых частотах, чтобы не было слышно периода:

```glsl
float flicker(float t) {
    return 0.85 + 0.15 * (0.5 * sin(7.1 * t) + 0.3 * sin(11.7 * t) + 0.2 * sin(19.3 * t));
}
```

Время бери из `SceneSettings::time` — это уже существующие часы анимации,
которые останавливаются клавишей `T`. На паузе мерцание обязано замереть.

### 5. Ночная палитра

Трогаешь: `Scene::background()`, цветовые полосы в `terrain.frag`, цвета
источников, цвет тела воды.

- Фон и туман — глубокий сине-чёрный, но **не чистый чёрный**: в чёрном не видно
  силуэтов гор, и критерий B2 «нет чёрных граней» провалится.
- Луна — холодная и неяркая, костёр — тёплый и насыщенный. Контраст тёплого
  пятна в холодной сцене и есть вся композиция.
- Полосы «луг → осыпь → скала → снег» сохрани, но пересчитай под ночь: снег
  остаётся самым светлым ориентиром силуэта.
- `Scene::background()` — единственное место, где живёт цвет фона. Оба шейдера
  получают его как `uFogColor`. Не вписывай цвет в шейдер константой.

### 6. Управление

- `F` — включить/выключить костёр.
- `M` + движение мыши — двигать луну (азимут и высота над горизонтом).
- `[` / `]` уже крутят азимут направленного света. Либо оставь их как
  быстрый способ без мыши, либо убери — но README должен описывать то, что есть.

В этом же коммите перенеси `F` и `M` из списка «запланированные биндинги» в
таблицу Controls.

## Подводные камни

- **Нормальная матрица.** Сейчас шейдеры считают `transpose(inverse(uModel))` на
  каждую вершину. Это чистая потеря; считай на CPU и передавай `mat3`. Делать
  необязательно, но если возьмёшься — это готовый ответ на вопрос комиссии.
- **Затухание.** Не бери `1/d²` без константы в знаменателе: вблизи источника
  получишь деление почти на ноль и белое пятно.
- **Спекуляр на плоских нормалях** даёт резкие пятна на целую грань. Так и
  должно быть при low-poly, но проверь, что это не читается как артефакт.
- **Слишком тёмная сцена** — провал B2 и B3 на видео. Проверяй кадр не только на
  своём мониторе.
- Блик на воде ищи, вращая свет: он виден, только когда источник **перед**
  камерой, а не за спиной.

## К защите

- Чем Блинн-Фонг отличается от Фонга и зачем нужен половинный вектор `h`.
- Почему освещение считается на фрагмент, а не на вершину, и что при этом
  меняется визуально.
- Что делает каждый член формулы затухания и почему там есть константа.
- Почему нормали нельзя умножать на модельную матрицу напрямую и откуда берётся
  обратно-транспонированная.
- Зачем нужна гамма-коррекция и почему она применяется один раз в конце.
