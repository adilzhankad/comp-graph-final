Четыре независимых куска работы. Каждый закрывает свой критерий рубрики и свой
набор файлов. Ниже — порядок, общий контракт и то, что считается «готово» для
любого из заданий.

|---|---|---|---|
| [01](01-lighting-and-night.md) | Освещение и ночная палитра | R4 / A3 (6 б.), B1 (5 б.) | — |
| [02](02-skybox-and-textures.md) | Скайбокс и текстуры | R5 / A4 (5 б.) | 01 (палитра) |
| [03](03-aurora-and-ui.md) | Аврора и интерфейс | «новая техника» темы, C3 (2 б.), B3 | 01 (ночь) |
| [04](04-props-hierarchy-and-trees.md) | Пропы, иерархия и инстансинг | R2+R3 / A2 (5 б.), A5 (4 б.) | 01 (свет) |

Плоское отражение в озере и волны смещением вершин остаются за владельцем
озера — это второй stretch-goal к A5.

**Задание 01 идёт первым и мерджится до остальных.** Оно задаёт палитру, против
которой все остальные тюнят свои модули. Пока 01 не влит, остальные могут писать
свои новые файлы (`Texture`, `Aurora`, `Props`), но не подключать их к сцене.

В `main` уже приехала бо́льшая часть задания 01, и двумя разными ветками:
прожектор маяка как второй движущийся источник света, ночная палитра со
звёздным небом и отражениями, и разрезанный `Scene::render` — твёрдый мир
рисует `renderEnvironment`, общий для зеркального и основного проходов. Бриф 01
это учитывает; сверяйтесь с ним, а не с этой строкой.

## Контракт интеграции

Нарушение любого пункта = конфликт при мердже или сломанная сборка у соседа.

**1. Ветки.** `feat/<короткое-имя>` от свежего `main`. Перед пушем — `git fetch
origin && git rebase origin/main`. Мердж в `main` через Pull Request, чтобы
остальные видели диффы.

**2. Проходы сцены.** После задания 01 у `Scene` на каждый объект свой приватный
метод (`renderTerrain`, `renderLake`, …). Добавляете свой объект — добавляете
**свой метод** и одну строку его вызова в `render`. Не трогайте тела чужих
методов.

**3. `SceneSettings`.** Свои параметры добавляйте в конец структуры, своим блоком
с комментарием. Не переставляйте чужие поля.

**4. Клавиши.** Биндинги уже расписаны в README в разделе Controls, включая
запланированные. Берите те, что закреплены за вашим заданием, и в том же
коммите переносите их из списка «запланировано» в таблицу. Свободные клавиши не
занимайте «про запас».

**5. `CMakeLists.txt`.** Свои `.cpp` дописывайте в конец списка исходников своей
строкой — тогда мердж сольётся сам. Не переформатируйте чужие строки.

**6. Ассеты.** Всё новое кладите в `assets/<ваша-папка>/`. CMake копирует
`assets/` и `shaders/` рядом с экзешником сам, трогать его для этого не нужно.
**Каждый ассет — строка в `CREDITS.md`: автор, ссылка, лицензия.** Без этого по
правилам курса −10 баллов и вплоть до нуля за проект.

**7. Новых зависимостей не добавлять** без согласования. Разрешены GLFW, GLAD,
GLM, stb_image, tinyobjloader, Dear ImGui, miniaudio/OpenAL — и только исходниками
в `external/`, собирающимися вместе с проектом. Ничего, что требует установки на
машине преподавателя.

## Что обязан сделать каждый

**Код**

- Собирается в Release и Debug **без единого предупреждения**. Флаги строгие:
  MSVC `/W4 /permissive-`, GCC/Clang `-Wall -Wextra -Wpedantic`.
- Ни одного файла длиннее ~500 строк (критерий D2). Класс = одна ответственность.
- Владелец GPU-ресурса — та обёртка, что его создала. Копирование запрещено,
  перемещение реализовано. Смотрите, как это сделано в `src/Mesh.cpp` и
  `src/Shader.cpp`, и делайте так же.
- Шейдеры — отдельными `.vert`/`.frag`, без BOM, никаких GLSL-строк в C++.
- Никаких закомментированных блоков и артефактов сборки в коммитах.
- Статические данные загружаются **один раз** на старте, не каждый кадр (B4).

**Проверка перед PR**

```bash
cmake -S . -B build -G "Visual Studio 17 2022" -A x64   # или ваш генератор
cmake --build build --config Release
cmake --build build --config Debug
cmake -E chdir build ctest -C Release --output-on-failure
cmake -E chdir build ctest -C Debug   --output-on-failure
build\Release\MountainLakeAurora.exe --smoke-test
```

Все шесть команд должны пройти. Скриншот своей фичи снимайте так:

```bash
build\Release\MountainLakeAurora.exe --smoke-test --capture my-feature.ppm
```

**Документация в том же PR**

- `README.md` — строка вашего требования в таблице R1–R8, таблица Controls,
  чекбокс фичи, раздел Technical notes с формулами вашего алгоритма.
- `docs/VALIDATION.md` — что собрали, что прогнали, на каком железе, что
  проверили глазами. **Не пишите цифры, которых не измеряли.**
- `CREDITS.md` — ассеты и любые заимствованные сниппеты.
- Таблица AI Use в `README.md` — если пользовались нейросетями, впишите чем,
  для чего и что сами изменили. Это требование курса, а не формальность.

**Коммиты.** Регулярно и от своего имени — рубрика D4 прямо смотрит, что
коммиты есть у каждого участника и размазаны по времени, а не свалены в
последнюю неделю. Сообщение объясняет **почему**, а не пересказывает дифф.

**Защита.** Вас спросят по вашей части: математику, шейдер, почему именно так.
В конце каждого брифа есть список вопросов — разберитесь с ними до защиты. Это
критерии A6 и F2/F4, они индивидуальные.

## Что уже есть в репозитории

Чтобы не писать заново:

| Что | Где |
|---|---|
| Компиляция/линковка шейдеров, кэш локаций юниформ | `src/Shader.h` |
| VAO/VBO/EBO, индексированная отрисовка, позиция+нормаль+UV | `src/Mesh.h` |
| Свободная камера, движение от delta time | `src/Camera.h` |
| Граф сцены: `local`, `world`, `addChild`, `updateWorld` | `src/SceneNode.h` |
| Карта высот: билинейная выборка, нормали, `heightAt(x, z)` | `src/Heightmap.h` |
| Уровень воды — одна общая константа | `src/World.h` |
| Куб, конус, усечённый конус и полый конус луча | `src/Primitives.h` (в сборке) |
| Маяк: башня, вращающийся узел лампы, луч | `src/Lighthouse.*`, `shaders/beam.*` |
| Прожектор как данные + его затухание | `src/Beacon.h` (в `mla_core`), `shaders/beacon.glsl` |
| `#include "file.glsl"` в шейдерах | резолвится в `src/Shader.cpp` |
| Прототипы авроры и шейдеры к ней | `src/Aurora.*`, `shaders/aurora.*` (не подключены) |
| Скайбокс, отражения, ночная вода | `src/Skybox.*`, `src/ReflectionTarget.*`, `shaders/lake.frag` |
| Обёртка 2D-текстур и кубмапы | `src/Texture.*` (пока ничем не используется) |
| Шейдер объектов: солнце, прожектор, туман | `shaders/object.*` (им рисуется маяк) |

`SceneNode` и `Heightmap` лежат в библиотеке `mla_core`, которая **не зависит от
OpenGL** — всё, что можно протестировать без контекста, кладите туда и пишите
тест в `tests/`.
